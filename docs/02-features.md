# 02 功能规格

本文只记录**你已经明确要求**的功能与**我补充的必要项**，细节后续对话再细化。标记「待定」的为尚未确定。

## 1. 主从控制（已定）

- 主程序（Hub）不直接控制任何容器的 Docker。
- 只有在线 Agent 所在机器，才能被操作。
- Hub 上看到的每台机器状态，均来自 Agent 上报。

**补充要求**：
- Agent 离线时，Hub 对该机器的操作按钮应置灰并提示原因，不能发一个永远不返回的请求。
- Agent 离线期间的待办指令可排队，重连后执行；但**危险操作不排队**（离线时删除请求应在第一时间拒绝而非延后执行）。

## 2. 编排文件双份（已定）

- 编排文件在 Hub 与 Agent 本地各一份。
- Agent 本地那份能脱离 Hub 独立生效，保证服务器自己也能维护部署。

**补充要求**：
- 双份文件必须带版本号与哈希，避免覆盖。
- 冲突时人工裁决，禁止自动合并（详见 01 架构文档 4.3）。
- Agent 本地的编排目录与文件命名需要固定规范，便于人直接 SSH 上去看和改。

## 3. 接管既有容器（已定）

- 通过宝塔等外部工具部署的容器与编排，要能被 Arkade 接管。
- 不是本工具部署的容器也要能纳入管理。

**补充要求**：
- 接管后打上来源标记（`adopted` / `discovered`），与 Arkade 部署的容器区分。
- 外部编排文件采用**只读快照**方式接管：读它、存快照、不写它，避免与宝塔抢控制权。
- 接管应支持“先发现后确认”流程：扫描出机器上的容器与编排，用户勾选哪些纳入。

## 4. 容器迁移（已定）

- 同时迁移：容器配置、容器镜像、存储卷。
- 支持迁移到其他服务器。
- 针对无外网仓库的服务器，支持本地镜像手动同步迁移。

**补充要求**（重要，缺了会出事）：
- **迁移前预检**：目标磁盘余量、运行时版本、卷挂载路径是否存在、镜像架构是否匹配（amd64/arm64）、目标端口占用、目标机器有无同名容器/编排。
- **停工策略**：数据卷不能边写边搬。迁移流程必须显式包含停机环节（或卷快照），不能做成“看起来在线迁移”的假象。
- **断点续传**：大镜像/大卷传输中断后可续，不必整包重来。
- **完成校验**：迁移后校验镜像 ID、卷内容哈希、容器启动健康。
- **回滚路径**：明确源容器是否保留、失败后如何回到原状。
- **迁移任务可观测**：进度、速率、剩余时间、当前阶段（预检/停容器/传镜像/传卷/起容器/校验）。

## 5. 镜像仓库统一授权（已定）

- 在主程序配置镜像仓库登录授权。
- 每台服务器通过该配置直接拉取镜像，不需要逐台登录。

**补充要求**：
- Agent 不持久保存仓库密码，改为向 Hub 换取短期凭据（或使用仓库临时 token 模式）。
- 支持多仓库并存与镜像前缀映射规则（例如统一改写 `registry.example.com/xxx` 到不同地址）。
- 支持各类仓库：Docker Hub、Harbor、阿里云 ACR、腾讯云 TCR、私有 registry。
- 拉取成功后应归档一次“凭据使用记录”，便于排查是谁拉了什么。

## 6. 补充建议项（我加的，待你确认）

以下是我的建议，不是你的要求，供你判断是否纳入：

| 项 | 为什么需要 | 优先级建议 |
| --- | --- | --- |
| 审计日志 | 多人使用时要能追溯“谁动了什么” | 高 |
| 权限分级 | 查看/操作/管理三档，避免误删 | 高 |
| Agent 版本协商 | 新功能下发到旧 Agent 会直接失败 | 高 |
| 容器状态实时推送 | 靠轮询刷新会卡且耗资源 | 中 |
| 批量操作 | 一次对多台机器/多个容器执行 | 中 |
| 定时任务/自动巡检 | 定时备份编排、巡检容器健康 | 中 |
| 通知渠道 | 容器挂了、迁移失败时推送告警 | 中 |
| 操作二次确认 | 删容器、清卷不可逆 | 高 |
| WebSocket 断线补齐 | 网络抖动后状态不能失真 | 高 |

## 7. 明确不做（避免范围膨胀）

- 不做 Kubernetes 全功能编排面板（如确有需要，AKS/K3s 按只读视图接入）。
- 不做镜像仓库服务器（不替代 Harbor）。
- 不做 CI/CD 流水线（只做部署与管理）。
