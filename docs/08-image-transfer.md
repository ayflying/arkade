# 镜像拉取、归档与服务器迁移

2026-11-10已部署至243并完成Docker真实API验收，以下为本批能力和边界，不代表所有引擎都通过真实验收。

## 操作语义

- 拉取：由所选Agent从公共镜像仓库拉取指定引用。首批不接收私有仓库账号密码，不等于仓库凭据管理。
- 导出：Agent生成Docker兼容镜像归档，任务成功后浏览器原生下载，不将整个文件读入网页内存。
- 导入：网页将本地tar文件流式上传；Hub边传边计算SHA256，Agent验证确切大小和哈希后调用引擎load。不是容器文件系统import，也不是恢复容器、网络或卷。
- 迁移：源Agent导出、Hub分块中转、目标Agent校验后load。只复制镜像，不启动容器、不删除源镜像、不迁移卷。导入可能更新目标已有同名标签，须明确确认。

取消只请求停止操作，不回滚已拉取的层、已入库镜像或已更新标签。跨引擎/跨CPU架构是否可运行取决于镜像内容和目标运行时，本功能不做平台转换。Podman需要单独真机验收。

## 传输与限制

控制通道维持Agent主动连接Hub，不新增Agent入站端口。大归档按256KiB分块请求传输，每块确认，内存使用与镜像总大小无关；公网高延迟会降低吞吐，首批不承诺断线续传或浏览器Range下载。

默认单归档2GiB，Agent传输区总配额4GiB、最多2个并发任务。Hub最多4个活动任务、128条内存历史。归档限制只保护传输临时区，不是引擎镜像层存储的磁盘配额：拉取及load仍要求宿主机有足够空间。

Agent归档在专用transfers目录，目录0700、文件0600；大小/哈希验证不需要在Hub落盘。归档可能包含业务代码或秘密，不能当公共文件分享。所有操作要求对应服务器manage权限；迁移要求两端manage；任务仅创建者或管理员可见，下载时重新校验授权。

Hub重启不保存任务历史；Agent重启清理本进程未登记的传输临时档案。成功导出保留约30分钟供下载，完整下载后释放；失败下载可在有效期内从头重试。待提交上传约10分钟过期，活动任务最长30分钟。

- 本地：Hub任务调度、所有者隔离、迁移确认、分块大小/哈希、取消、失败重试与释放测试；前端构建及接口契约断言。
- 243真实Docker：公共alpine:3.20拉取；导出并下载3731968字节归档，删除专用测试标签后上传导入恢复；同服务器迁移被拒。
- 跨Agent：临时专属接入Agent连接独立vfs Docker引擎，从243源引擎迁入镜像；目标RootFS层、平台和Config一致、目标零容器、源标签保留。源containerd镜像存储返回index digest、目标经典存储返回config digest，因此不以两端Id字符串相等作为一致性标准。没有在其他业务容器执行启停或删除。
- Linux隔离测试容器：Agent imagetransfer/runtime及Hub imagetask的go test -race通过；符号链接防护测试在Linux实际执行。
- 测试环境事故与恢复：临时dockerd即使bridge=none仍在退出时移除宿主默认docker0。已停止此测试方式，并按宿主既有172.17.0.0/16配置精准重建docker0、将act-runner既有veth重新接回；验证该容器可达网关172.17.0.1及192.168.50.1，未重启业务容器或宿主Docker。后续第二引擎验收必须使用独立网络命名空间或独立主机，不能仅靠不同data-root。
- 临时Agent记录、容器、源测试标签和独立引擎数据目录已清理。浏览器完整交互和Podman真实行为尚未逐项验收。
