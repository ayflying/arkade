# 用户、权限、系统设置与 OIDC 登录

## 交付范围

基于现有数据库用户和会话实现统一登录，不增加平行账号体系。新增用户/用户组管理、有效权限预览、个人设置、本地注册开关、系统设置、Casdoor/通用 OIDC 提供方管理。前端管理入口仅管理员可见，后端独立校验，隐藏按钮不能代替授权。

### 用户与授权

- `admin` 是全局系统管理员；`user` 通过一个或多个用户组获取服务器权限，同服务器取最高级别。
- 档位为 `none < view < operate < manage`。服务器 manage 不允许普通用户管理系统、用户或用户组。
- 创建/重置临时密码后强制先改密；仅资料、改密、me 和退出入口可用，不能继续访问业务或系统设置。
- 有效权限预览由后端计算并展示来源组；禁用账号的有效权限为 none，保留授权来源供管理员排查。
- 删除、禁用、降级最后一个可用的本地管理员会被事务性拒绝，OIDC 管理员不计入本地应急入口。
- 改密校验原密码，拒绝相同密码，成功后撤销所有会话并要求重新登录。禁用账号立即阻止会话认证。

### 注册和系统设置

- 本地注册默认关闭。管理员可在系统设置开启，并可选择默认用户组；不选组即没有服务器权限。
- OIDC 首次自动开户与本地注册是独立开关。本地注册关闭不影响管理员显式允许的第三方自动开户。
- 自动创建账号只允许普通角色，不接受客户端传入角色、用户组或外部角色声明。
- 注册提交在事务中复核开关、设置版本和默认组；成功返回 201，不自动登录。
- 系统设置支持站点名称、登录说明、默认注册组、会话 TTL、密码最小长度、失败限流和审计保留天数。更新带 version，过期修改返回冲突，避免覆盖他人设置。
- 本地密码登录保持开启。新会话采用实时 TTL，旧会话保留原到期时间；修改期限不会追溯延长或缩短已签发会话。
- 数据库会话策略默认 TTL 为 24 小时，由系统设置管理，不从启动环境变量导入已有策略。
- 密码策略为 8–72 字符的最小长度设置，实际提交另受 bcrypt UTF-8 72 字节上限约束。初始默认最小长度为 12；管理员初始引导密码仍遵循既有启动配置校验，创建和重置用户使用动态策略。
- 限流按用户名、实际连接 IP 独立计数并预占并发；成功验证不累计失败预算，不信任任意转发 IP 头。反向代理后 IP 配额可能由多个用户共享，应结合网关限流部署。
- 审计默认保留 90 天。worker 启动立即按策略清理，之后每 6 小时重新读取保留天数（1–3650），失败重试；修改天数在下次清理周期生效，只删除早于截止时间的记录。写审计和打开数据库不再按隐式条数上限删除历史。

## Casdoor 配置步骤

1. 为 Arkade 设置稳定的公开访问地址 `server.base_url` / `ARKADE_BASE_URL`，生产使用 HTTPS。不要使用用户可控 Host 头推导回调地址。
2. 在 Casdoor 创建 OIDC 应用，启用 Authorization Code，并允许 PKCE S256。申请 `openid profile email`（可调整，但必须含 openid）。
3. 管理员在 Arkade 系统设置 → 第三方登录中新建提供方，填显示名称、Casdoor 的精确 Issuer、Client ID 和 Client Secret。Issuer 必须与 discovery 文档及 ID Token 完全一致，尾部 `/` 有语义，不自动去除。
4. 保存后复制 Arkade 展示的固定回调地址到 Casdoor 允许的 redirect URI，格式为 `https://你的域名/api/auth/oidc/<提供方ID>/callback`。
5. 若希望首次登录自动开户，开启该提供方的自动注册，可选择默认组；不选择则无服务器权限。否则只有已绑定身份能登录。
6. 启用提供方，使用“测试连接”验证 discovery，然后从登录页的对应按钮进行实际授权验证。“测试连接”不等于账号登录或权限验收。
7. 保留本地管理员，以便身份平台故障或配置错误时恢复。不要将身份平台的 admin/group 声明直接授予 Arkade 管理权限。

Casdoor 首期采用标准 OIDC，不包含 SAML、LDAP、用户组自动同步、登出联动或第三方账号密码代管。

## 身份绑定与安全

- 唯一身份为提供方 ID + `sub`，不按昵称、邮箱相同自动合并账号。
- 已登录的本地账号需要重新验证当前密码后才能发起绑定；回调必须匹配同一用户和同一会话。纯 OIDC 账号暂不支持此绑定入口，也不支持自行设置本地密码，页面明确说明。
- OIDC 自动开户使用无本地密码哈希的用户，不能用空密码或第三方密码登录 Arkade。
- 已有身份绑定的提供方禁止更改 Issuer 和 Client ID，防止新身份源的相同 sub 接管旧账号。迁移应新增提供方，密钥轮换仍允许。
- 删除或禁用提供方、解绑身份时保护最后一种可用登录方式；禁用用户、提供方变化、身份归属在签发会话事务里再次检查。
- Authorization Code + PKCE S256；state、nonce、浏览器绑定令牌独立随机生成。state 有效期 5 分钟、一次性使用、实例内最多 1024 个；重启后未完成流程失效，当前单实例设计不支持跨节点共享。
- 成熟 OIDC 库验证签名、issuer、audience、expiry；校验 nonce。只允许本地相对跳转，拒绝协议相对路径、反斜杠、编码控制字符等。
- 写请求拒绝跨站 Origin / Sec-Fetch-Site。会话及流程 Cookie 使用 HttpOnly、SameSite=Lax；公开地址为 HTTPS 时流程 Cookie 使用 Secure。
- 提供方密码仅接收替换，管理端和公开端均不返回明文或密文；编辑留空代表不提交替换。密钥不进入访问日志和审计，OIDC code/state/token/claims 不进入审计。反向代理或外部网关的访问日志也应对 callback 查询参数脱敏，本应用的日志策略不会自动修改网关日志。
- Discovery/Token/JWKS 有超时、响应体上限和重定向限制。允许受信管理员配置私网 HTTPS 身份平台及跨域 HTTPS 端点，未实施 DNS/私网地址 SSRF 沙箱，应控制管理员和出站网络。

## 主密钥与备份

PostgreSQL 版本化建表包含设置、OIDC 提供方、身份绑定和首次改密字段。DAO/DO/entity 由项目 GF 生成器从实际迁移的 PostgreSQL 数据库生成，不手工维护。

Client Secret 使用独立随机 32 字节主密钥进行 AES-256-GCM 加密，随机 nonce 并绑定提供方 ID。主密钥默认位于 `./data/settings.key`，容器编排显式指定 `/data/settings.key`，与 PostgreSQL DSN 完全解耦，可用下列部署项覆盖：

```toml
[auth]
settings_key_file = "/run/secrets/arkade-settings.key"
allow_insecure_oidc_loopback = false
```

对应环境变量 `ARKADE_SETTINGS_KEY_FILE`、`ARKADE_ALLOW_INSECURE_OIDC_LOOPBACK`。后者仅本地测试允许 HTTP loopback Issuer；生产保持关闭，前端配置页默认只接受 HTTPS。

- Linux 密钥文件必须为普通文件且权限不宽于 0600；拒绝符号链接、错误长度或损坏格式。Windows 应用不修改系统 ACL，部署者需限制所在目录访问权限。
- 第一次使用无凭据的新库可以自动生成密钥；已有加密凭据但密钥遗失时启动拒绝，不自动生成替代密钥。
- **数据库和密钥必须一起备份、一起恢复。单独复制数据库不能解密第三方密钥。** 数据库快照命令只备份数据库，不假称已包含外部密钥文件。
- 密钥文件不能加入 Git、容器镜像或公开日志。当前不提供网页主密钥轮换操作。

## 验证与边界

实现阶段先修复了真实 HTTP 验收发现的 OIDC `/api` 前缀遗漏：公开 options 返回地址、路由、固定回调和私有身份接口现统一 `/api`。另外独立审查修复了 Issuer 尾斜杠归一化、替换已绑定提供方的身份源接管风险及遗失主密钥自动替换风险。

- Windows Go 1.24.13：Hub 全包 912 个测试/子测试通过、40 个有测试包通过，零失败，vet 通过；跨包语句覆盖率 77.0%，不是分支或业务 100% 覆盖。Agent 全包测试及 vet、protocol 编译检查及 vet 也重新通过。
- 前端 15 套契约测试，共 1233 次断言通过，包括真实 TypeScript API 调用、权限导航、秘密省略、CAS 和组件编译；不是 1233 个浏览器场景。
- Linux Go 1.24.13 对最终 Hub 全包执行测试：912 个测试/子测试、31 个有测试包全部通过（Windows 额外包含平台专属包）。另对 auth/store/account/settings/oidclogin/auditretention 六包执行真实 race，全部通过。
- 真实签名/JWKS 测试身份平台覆盖 code、PKCE、nonce、签名/issuer/audience/expiry、state 重放及错误浏览器、绑定会话、provider 版本/禁用及普通身份落库。完整真实 HTTP OIDC 14 条用例在最终构建后连续三次通过（共 42 次），直接使用公开 options 的登录入口并逐跳验证 Cookie，不用硬编码错误路由迁就实现。
- 浏览器能打开独立本机临时环境并填写登录表单，但点击交互遇到浏览器扩展受限 frame 错误，登录提交结果未知，未声称登录后的页面验收通过。
- 未取得真实 Casdoor 实例互操作、JWKS 轮转并发刷新或生产部署验收证据；不将标准 OIDC 测试平台通过包装成真实 Casdoor 已测。现有业务部署未替换。
