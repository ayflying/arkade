# 统一编排列表与详情

## 信息组织

参考Portainer Docker Standalone的编排详情组织方式：容器、配置、日志是同一项目的不同视图，而不是按登记状态拆成两套界面。沿用Arkade现有运维界面样式，不复制Portainer未实现的能力。

- 一个编排表，按名称合并引擎项目与Hub记录，同名以Hub记录为准；配置来源、同步与登记原因作为列信息。
- 一个详情入口与页面壳，默认显示容器，统一容器/配置/日志标签。旧外部详情地址保留跳转兼容。
- 容器表展示名称、镜像、运行状态、网络/IP、实际映射端口和创建时间，名称可进入容器详情。网络/IP一次容器列表返回，不逐容器inspect；host网络明确显示“主机网络”，不把服务器IP伪装成容器IP。

## 运行边界不随视觉统一而混淆

统一列表不等于强制搬迁服务器项目。已有容器可直接管理；外部项目的配置可以读取和保存Hub草稿，但尚未支持原目录写回与执行。已登记项目的“保存并部署”会下发compose up，因此必须清楚提示并确认，不能宣传为保存草稿。环境文件仍使用省略保留、空串清空的三态语义。

配置正文、环境文件和草稿需要manage，运行元数据和日志沿用view。不得为了显示IP将管理权限inspect字段泄露给view。错误与离线不假装成零容器，界面应显示读取失败并允许刷新。

## 配置代码编辑器

Compose正文统一使用本地打包的YAML代码编辑器，提供行号、语法高亮、两空格缩进、Tab/Shift+Tab缩进与撤销重做；配置面板、新建和导入复用同一组件，不依赖CDN或发送配置到第三方。代码高亮不等于Compose语义校验，部署前仍使用服务端校验与明确确认。只读或保存中不可修改，但保留内容选择和复制；编辑器卸载时销毁实例，避免配置残留在游离DOM。

## 服务端兼容契约

GET /api/agents/{id}/stacks/{name}统一返回stack、containers与可选containers_error。stack.managed表示Hub有配置记录，不表示容器能否管理。已登记项目离线仍返回Hub元数据和容器读取错误；外部项目无法连接引擎时返回503，而不是声称不存在；在线确认无项目才404。详情读取不创建登记、不触发生命周期操作。

参考资料：[Portainer编排详情](https://docs.portainer.io/user/docker/stacks/edit)、[Portainer容器详情](https://docs.portainer.io/user/docker/containers/view)。
