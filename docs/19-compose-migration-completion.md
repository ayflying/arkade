# 跨服务器 Compose 迁移：实现与验收

2026-11-11。承接 GoFrame 原生迁移后未装配的业务缺口，本轮完成生产启动接线、真实 Agent 迁移能力、传输 backend、任务生命周期和前端安全交互。既有 Hub/Agent 部署未被替换；相关代码需由操作员更新后使用。

## 使用语义

- 源、目标必须不同且在线；发起和读取日志重新校验双端 manage，任务仅发起者或管理员可见。
- 配置与 `.env`、镜像必迁；卷默认不迁，目标默认不启动。最终确认明确展示实际选择。
- 仅支持托管编排作为源；Hub 权威版本与 Agent 配置/env/hash 不一致时拒绝。镜像和卷标识由源引擎规范化，不在 Hub 猜项目前缀。
- 目标有同名托管或外部 Compose 项目均拒绝；不覆盖已有数据卷，不停止/删除源容器、配置、镜像或卷。
- 迁移不是事务回滚：镜像可能已导入、卷可能已创建或部分恢复，配置写入和启动也可能遇到确认丢失。失败日志报告确认残留与 uncertain，用户先检查目标再决定后续操作。
- 相同发起者、相同 request_id、相同参数复用任务；参数不一致拒绝。网络不确定时前端冻结原参数，避免同键变成另一项迁移。

## 实现

1. 生产 NewApp 构造 stackmigration backend 和 stackmigrate manager；退出先取消、等待迁移完成清理，再关闭 Agent 通道及数据库。
2. 新 Agent RPC 提供真实 Compose migration plan、create-only 配置导入，以及卷归档/分块导入/状态/取消。Compose 项目锁保护检查与写配置，目标 DB 仅唯一插入、不 UPDATE 覆盖。
3. 镜像、卷均 256 KiB 有界分块，确切长度、offset、ACK、SHA-256 校验后提交；Compose project hash 为既有 16 位协议，不与归档 64 位 SHA-256 混用。
4. 卷创建带随机 ownership 标签，随后 inspect 核验归属才解包；同 Agent 原子预留任务，并用可取消恢复槽串行化提交。已有卷不会因 Docker create 的幂等行为而被误认作新卷。
5. tar helper 使用随机名和归属标签，network none。取消不仅终止 CLI，还以独立 context 核验并删除本任务 helper；清理不能确认则显式报错、保留临时目录，不能假报已释放。
6. manager worker 保留身份但脱离 HTTP 取消，支持 Close 等待；服务端请求取消也将等待任务转终态，避免永久占用同卷预留。并发幂等、限额、反向服务器对锁、日志内存及 panic 收敛均有回归。

## 真实隔离验收

在 192.168.50.243 创建两套临时 Docker 29.9.2 引擎。每套独立 network/mount namespace、data-root、exec-root、Unix socket 和显式独立 containerd；不在宿主网络命名空间运行第二引擎。容器使用 network_mode none，不拉公网镜像，alpine:3.20 从既有引擎只读 save 后导入。

临时 Hub 从生产 NewApp 启动，两个新 Agent 使用实际 WebSocket；测试从真实 HTTP API 发起，不用假 backend 绕过 RPC。

已验证：

- 默认迁移成功，目标配置和镜像存在，目标没有运行容器，也没有源卷数据。
- 显式迁卷并启动成功，目标卷 sentinel 内容一致，源卷仍在。
- 源容器 ID、StartedAt、RestartCount 在迁移前后完全一致。
- 目标已有同名托管项目拒绝，目标容器和数据保持不变。
- 目标已有同名卷拒绝，不解包、不写目标配置，原 marker 与持有容器生命周期不变；之前已导入的镜像数量如实报告。
- 目标外部同名项目拒绝，原外部容器、卷 marker 和源容器保持不变。
- 最终候选二进制再次在全新项目重复成功和失败路径，不将旧幂等任务当成新验收。

期间其他任务在宿主新增了一个非本项目容器。对原 baseline 容器逐一核对 ID、启动时间、重启次数未变，宿主 docker0 与路由未变；不将“原有业务未改”夸大为“宿主所有状态从未变化”。清理只操作本次 manifest 下核验过的私有引擎、临时应用与测试资源，保留日志证据，不全局 prune、不删除业务数据。

## 不应误解的边界

- 正在写入的数据库卷归档不是应用一致性快照，关键业务应先自行安排一致性策略；工具不会擅自停源。
- bind mount 和匿名卷不迁，显示跳过项。显式/外部命名卷会复制，但目标已存在则拒绝。
- 不做 CPU 架构转换，不保证任意业务配置在新主机可运行，目标端口、外部依赖、路径和容量仍由操作员确认。
- 有其他拥有 Docker 管理权的进程主动删除/重建资源时，不提供对抗式全局事务保证；本项目内部的项目锁、随机归属校验与拒绝覆盖不是 Docker 之外的全局锁。
- 当前已完成 Docker 双引擎验收；不将其当作 Podman 真机验收，也不默默扩展为所有运行时/平台都已实测。
- Hub 重启不保存迁移任务历史；不承诺跨 Hub 重启续传。配置/镜像/数据已经发生的改动不会因任务历史过期而回滚。
- 手动部署须同时更新 Hub 与迁移涉及的 Agent，以获得新 RPC；参考手动部署文档。既有测试服与 GHCR latest 未由本轮替换。
