# 容器监控与通知

## 功能与边界

Arkade 由 Hub 定时请求只读监控快照：本机默认通过内置执行器与内部 Registry 调用，远程服务器通过反向连接的独立 Agent。展示容器运行状态、健康检查、CPU、内存、网络与磁盘速率，并在异常持续后通过钉钉或邮件通知管理员。采集不启动、停止、重启容器，不修改 Compose 文件，也不执行自动修复。新拓扑与同机升级边界见 [内置本机执行](<21-embedded-local.md>)。

- 入口为管理员的 **系统设置 → 监控与通知**；配置、测试及状态接口均由后端独立限制为管理员。普通用户即使有某台服务器的查看或管理权限，也不能读取全局通知配置。
- **默认关闭**，钉钉和邮件通道也默认关闭。打开网页不是启动监控的条件：保存启用后由 Hub 后台持续执行；离开此 tab 只会停止浏览器的状态刷新。
- 这是最新指标及告警记录，不是历史时序监控系统；目前没有历史趋势图、任意时间范围查询或指标长期存储承诺。
- **没有健康检查不代表健康**。只有容器配置了健康检查，才能根据其 `healthy` / `unhealthy` 结果判断健康检查是否通过。
- **服务器失联不代表确定宕机**：也可能是网络、代理、Agent 进程或连接异常。失联时不会将该服务器所有容器批量判为宕机，也不会把缺少样本当作恢复。
- **本机 `online` 不代表 Docker 健康**：它只表示 Hub 进程内执行可用，不依赖本地 WebSocket/Token。Docker socket 不可达、权限错误或引擎异常须通过运行时与采集错误判断；运行时为 `none` 时，List 为兼容可成功返回空集合，但不代表 Docker 零容器或健康；监控采样与实际控制不支持，不是零占用或健康。
- **Hub 自身停止时无法为自己发送告警**，内置本机执行与采集也随 Hub 停止。请另配独立的外部可用性监控；不要将 Hub 与所有告警链路放在同一故障域后期待它自报警。Hub 运行期间仍可监控远程 Agent 的失联，但不能据此推断远程宿主确定宕机。此功能不提供 Hub 自愈或容器自动修复。

## 升级与首次启用

1. 先备份 PostgreSQL、Hub 的设置加密主密钥与本机工作卷。Hub 默认内置本机执行，本机采集能力随 Hub 更新；远程服务器仍需更新独立 Agent，使 Hub 与远程 Agent 都支持监控协议。只升级 Hub 时，旧远程 Agent 不能采集新快照，可能出现采集失败事件，并不意味着容器已经停止。同机旧 combined 部署须先停旧 Agent，保持原 project 和 `arkade-agent-data` 卷，再用新编排 `up -d --remove-orphans`；不得删卷。
2. 以管理员登录，打开 **系统设置 → 监控与通知**，核对“监控能力与边界”说明。
3. 设置采集与告警规则，按需要填写排除列表。先不启用通知也可以保存和观察指标。
4. 配置钉钉或 SMTP，勾选需要启用的通道，点击 **保存监控与通知设置**。
5. 保存成功后，点击 **测试钉钉（请先保存）** 或 **测试邮件（请先保存）**。测试使用服务器上已经保存的配置，不读取尚未保存的表单内容；有未保存修改时测试按钮不可用。测试消息不代表发生故障。
6. 查看接收端和下方通知投递记录，确认链路可用，再开启后台监控并保存（也可与通道配置一起开启）。等待至少一个采集周期；速率通常需要连续两个有效样本。

表单显示当前版本和未保存状态。保存使用版本比较，其他管理员先保存会导致版本冲突；此时保留当前输入，不自动覆盖他人设置。请先记下修改，再点击 **重新读取设置**，确认丢弃当前输入后载入最新配置并重新编辑。状态刷新不会重读配置或覆盖输入。切换离开监控 tab 会卸载页面，未保存输入不会保留。

## 规则与默认值

| 项目 | 默认值 | 可设置范围与含义 |
| --- | --- | --- |
| 后台监控 | 关闭 | 保存启用后由 Hub 执行 |
| 采集间隔 | 30 秒 | 10–3600 秒；每轮完成后等待下一间隔，不是硬实时保证 |
| 异常持续时间 | 120 秒 | 0–86400 秒；0 表示采到异常即进入告警 |
| 重复通知间隔 | 1800 秒 | 60–604800 秒；异常持续时按此节流 |
| 服务器失联判定 | 120 秒 | 30–86400 秒；达到失联阈值后告警，不再叠加容器异常持续时间 |
| CPU 阈值 | 80% | 大于 0、不超过 12800%；一个逻辑核的占用为 100%，多核容器可以超过 100% |
| 内存阈值 | 80% | 大于 0、不超过 100%；需要有效内存限制与统计数据 |
| 恢复通知 | 开启 | 对曾成功送达异常通知的通道发送恢复通知 |

监测包括健康检查失败、重启/重启次数增长、异常退出、CPU/内存超限、服务器失联与采集异常。资源采集不可用不是“占用为零”，快照不完整也不是“全正常”。通知失败按通道重试，成功通道不会因为另一个通道失败而在每轮重复发送；外部通知无法保证严格只投递一次，故障重试时仍可能重复。

### 停止状态与后台操作抑制

- 首次观察到已经停止的容器，不直接发送异常退出告警；需要先观察到其运行，再观察到非零退出码的退出或 `dead` 状态。正常退出码 0 的停止不按异常退出处理。
- 从 Arkade 后台执行单容器停止、重启或删除操作时，对目标容器设置 **5 分钟**计划操作抑制，减少部署维护产生的误报。通过外部 Docker CLI 执行的操作不会自动获得这段抑制。
- 后台 Compose 的 `up`、`down`、`stop`、`restart`、`remove` 目前按 **该 Agent 整台服务器的容器范围**抑制 5 分钟，而不是只精确抑制该项目；维护期间其他容器也可能暂不告警。
- 容器操作抑制不用于屏蔽服务器失联告警。已抑制的容器事件会静默结束，不因计划操作发送恢复通知。

### 排除对象

输入后按回车生成标签，删除标签后保存即可取消排除。

- **服务器**：填写精确的 Agent ID，不是显示名称；匹配后跳过该服务器的采集和告警。
- **容器**：填写快照中的完整容器 ID，或容器的精确名称。区分大小写，不做短 ID 前缀、正则或通配符匹配；不要照搬单容器操作支持的短 ID。
- 容器列表是全局排除条件，不带服务器作用域；相同名称会排除所有服务器上同名的容器。如需只排除一个实例，使用其完整 ID。
- 名称按页面指标中的名称填写，不额外添加 Docker 展示时可能带的前导 `/`。列表每类最多 2000 项，每项 1–256 字节。

## 钉钉机器人

1. 在目标群创建自定义机器人，复制官方 Webhook，例如 `https://oapi.dingtalk.com/robot/send?access_token=你的令牌`。
2. 在 Arkade 填入完整地址。只接受该官方 HTTPS 地址及单个 `access_token` 参数；不要附加自己生成的 `timestamp` / `sign`，也不支持自定义转发地址。
3. 推荐开启钉钉机器人的 **加签**，把机器人提供的签名密钥填到 Arkade 的“签名密钥”。Arkade 在发送时计算签名。请保持 Hub 系统时钟准确。
4. 如果钉钉还要求自定义关键词，请配置包含 **`Arkade`** 的关键词。告警和测试消息标题都包含 `Arkade`；不要只填某一种异常的中文名，否则测试或恢复通知可能不匹配。
5. 勾选启用钉钉通知，保存后发送测试；确认机器人仍在群中、网络可访问钉钉、加签与关键词策略一致。

Webhook 含访问令牌，保存后不会回显，只显示是否已配置。**更换 Webhook 地址不会复用原签名密钥**：需要同时填新签名密钥；未填时旧签名密钥会被清除，防止把旧密钥带给新目标。只改其他规则且不更换地址时，密钥留空保持原值。

## SMTP 邮件

填写 SMTP 主机（只填主机名/IP，不带协议或端口）、端口、传输加密方式、用户名、密码、发件人和收件人列表。收件人逐个输入后按回车，最多 100 个；发件地址须符合邮件服务商的授权要求。

- **STARTTLS**：通常使用 587 端口，先连接 SMTP 再强制升级 TLS；服务器不支持 STARTTLS 时发送失败，不降级明文。
- **TLS**：通常使用 465 端口，连接建立即进行 TLS 握手。端口以邮件服务商说明为准，不由选项自动决定。
- TLS 最低版本为 1.2，验证证书及 SMTP 主机名；不提供跳过证书验证或明文传输选项。自建邮件服务器需让 Hub 信任相应 CA。
- 使用账号认证时，用户名与密码必须同时配置；部分服务商要求专用 SMTP 授权码而非登录密码。支持无需账号认证的受信 SMTP 中继时，两项同时留空，但仍要求加密连接。
- **已有密码时更换主机、端口、加密方式或用户名，必须重新填写密码或明确勾选清除密码**，否则保存被拒绝，防止新目标收到旧凭据。清除密码但保留非空用户名仍会违反账号/密码成对校验，应同时调整用户名。

保存后测试。发送成功表示 SMTP/钉钉服务接受本次请求，并不保证邮件未被垃圾邮件策略拦截，也不保证所有群成员已阅读通知。失败提示会有意隐藏服务端原始响应，避免其中夹带令牌或密码。

## 指标、历史与排查

- 浏览器仅在监控 tab 挂载且页面可见时每 15 秒刷新状态；这是页面刷新频率，和 Hub 的采集间隔独立。
- 网络/磁盘速率来自连续样本的计数器差值。首个样本、计数器重置或缺少有效统计时显示速率暂不可用，不把缺少样本伪装成 `0/s`。
- 超过 **采集间隔的 3 倍且至少 90 秒**没有新值时，运行状态、健康检查及资源值标为“已过期”。采集时间是 Hub 接收时间；查看过期提示和错误，不要把缓存值当成实时结果。
- 快照列标识是否完整；无统计数据、快照不完整、采集失败均需要排查 Agent 版本、运行时权限、网络与容器状态，不能据此推断业务健康。
- 页面分别显示最新最多 **200 条告警事件、200 条投递记录**，表格分页仅对当前返回的记录分页，不是遍历全量历史。
- 投递记录与已结束告警按 **30 天**保留期定期清理；未结束事件不会因到期清理。告警记录按对象和类型复用，同类异常再次发生时会更新记录，不是每次异常都形成一条永久独立事件。

无指标时先检查已保存的总开关、排除列表及最近采集时间。本机还需检查本机执行开关、是否沿用旧 disabled 标记、Docker/Compose 安装与 socket 权限；本机显示 online 不能代替这些检查。运行时为 `none` 时监控采样不支持，List 成功返回的兼容空集合也不是健康样本。远程服务器则检查 Agent 在线、版本及连接。没有通知时再检查通道启用开关、异常持续时间、5 分钟计划操作抑制、重复通知间隔，以及投递失败记录。测试使用已保存配置，改完凭据后务必先保存。

## 通知凭据与备份

通知凭据使用 Hub 已有的设置主密钥进行 AES-256-GCM 加密；钉钉完整 Webhook、签名密钥和 SMTP 密码不出现在配置读取响应中。页面只显示“已配置”标记，未更换目标时空输入保持原值，显式清除才删除。

**数据库和原设置主密钥必须一起备份、一起恢复。** 主密钥由 `auth.settings_key_file` / `ARKADE_SETTINGS_KEY_FILE` 指定，默认 `./data/settings.key`，现有容器编排为 `/data/settings.key`。只备份 PostgreSQL 无法恢复通知凭据。不要把密钥放进 Git、镜像或日志；遗失后不能靠重新生成同名文件解密。部署项和权限约定见 [用户与设置：主密钥、升级与备份](<21-users-settings-oidc.md#主密钥升级与备份>)，升级流程见 [手动部署与回退](<18-manual-goframe-deployment.md>)。

只读采集表示不修改被管容器，不表示无需权限：Hub 的内置执行器和远程 Agent 均需合法访问各自宿主的容器运行时。容器版 Hub 以 root 持有 Docker socket 权限，近似宿主 root；全局监控页面与通知目标应只交给受信管理员。邮件目标允许管理员配置内网 SMTP，部署者仍应控制 Hub 的出站网络和管理员账号。
