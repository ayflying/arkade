# 04 路线图

> 本文件只是初步分期，具体功能细节在后续对话中细化后重排。
> 已拍板的决策见 [05 已决策项](05-decisions.md)。

## 第一阶段：骨架打通（最小可用）

目标：Hub 与 Agent 能连上，能看能管。

- [ ] Hub：Web 服务骨架、用户登录、Agent 注册与鉴权
- [ ] Hub：WebSocket 连接管理、在线状态、心跳
- [ ] Agent：反向连接、心跳、重连、离线自治
- [ ] Agent：运行时探测与容器列表/启停/日志
- [ ] Web：登录、服务器列表、容器列表与基础操作
- [ ] 消息信封协议 v1 定稿

**验收口径**：至少一台 Agent 连上 Hub，能在网页看到容器列表并启停；断网后 Agent 仍可本地操作。

## 第二阶段：编排与接管

- [ ] 编排双份存储（版本 + 哈希）
- [ ] 冲突检测与人工裁决界面
- [ ] Agent 本地编排独立执行
- [ ] 扫描发现既有容器与外部编排（宝塔等）
- [ ] 接管流程与来源标记
- [ ] Compose 兼容的编排编辑与部署

**验收口径**：宝塔部署的一套容器能被接管并正常展示；Hub 与 Agent 各自改编排后能正确提示冲突。

## 第三阶段：镜像与仓库

- [ ] 镜像仓库凭据集中配置
- [ ] Agent 短期凭据换取机制
- [ ] 镜像前缀映射规则
- [ ] 本地镜像列表、拉取、删除、打标签
- [ ] 点对点本地镜像同步（无外网场景）

**验收口径**：在一台未登录任何仓库的服务器上，凭 Hub 的授权配置成功拉取私有镜像。

## 第四阶段：迁移

- [ ] 迁移预检（磁盘、版本、架构、端口、路径）
- [ ] 配置 + 镜像 + 卷打包迁移
- [ ] 断点续传
- [ ] 完成校验与回滚
- [ ] 迁移任务进度可视化

**验收口径**：两台服务器间完整迁移一个带数据卷的服务，迁移后服务可用、卷数据一致；中途断网后可续传完成。

## 第五阶段：管理能力补强

- [ ] 审计日志
- [ ] 权限分级
- [ ] 批量操作
- [ ] 定时备份与巡检
- [ ] 通知告警
- [ ] Agent 版本协商与灰度升级

## 第六阶段：多引擎扩展

按后续确认的范围，逐步接入 Podman / containerd 等，统一到「运行时抽象层」下。

## 明确不在早期范围

- Kubernetes 全功能编排面板
- 替代 Harbor 的镜像仓库服务
- CI/CD 流水线
