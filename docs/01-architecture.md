# 01 架构设计

> **2026-11-13 架构覆盖声明：Hub 默认内置本机执行，只有远程服务器需要独立 Agent。**
> 本文以下保留最初的架构设计与探索记录；其中「Hub 绝不访问运行时」「所有服务器必须经独立 Agent/WebSocket」「Hub 不持有 docker.sock」等表述已被本声明覆盖，不能再作为当前实现红线。
> 本机复用 `agent/embedded` 公开包，经内部 Registry 直接调用，不启动本地 WebSocket、不签发本机 Token；固定 `agent-local`，容器工作目录 `/data/local`，与设置主密钥共用一个 `/data` 数据卷。远程 Agent 继续主动反连 Hub。
> `ARKADE_LOCAL_ENABLED=false` 或 `local.enabled=false` 可关闭本机执行，重启生效；Hub 仍依赖 PostgreSQL。启用本机时 Hub 需要 Docker/Compose 及运行时访问权限，容器版以 root 持有宿主 socket；这扩大了 Hub 的信任边界，不是隔离沙箱。
> 本机 `online` 表示进程内执行可用而不是 Docker 健康，运行时为 `none` 时，List 可成功返回空集合，不代表 Docker 零容器或健康；监控采样与实际控制不支持。Hub 停止时内置执行与自身通知均不可用，不提供自愈承诺；Hub 运行期间仍监控远程失联。
> 当前部署及本机记录管理约束以 [内置本机执行](<21-embedded-local.md>) 为准；数据库相关旧描述由 [D-03 PostgreSQL 决策](<05-decisions.md#d-03-hub-存储postgresql全新数据库>) 覆盖。

## 1. 总体拓扑

```
        ┌────────────────────────────────────────────┐
        │              主程序 Hub（控制面）            │
        │  Web 前端 / 用户鉴权 / Agent 注册与心跳      │
        │  编排仓库 / 凭据中心 / 迁移任务编排 / 审计    │
        └────────────────┬───────────────────────────┘
                         │  WebSocket（TLS + 双向认证）
                         │  Agent 主动连入，长连接
        ┌────────────────┴───────────────────────────┐
        │                                            │
   ┌────▼────┐                                  ┌────▼────┐
   │ Agent A │                                  │ Agent B │
   │  服务器1 │                                  │  服务器2 │
   └────┬────┘                                  └────┬────┘
        │ docker.sock / podman socket / containerd   │
   ┌────▼────┐                                  ┌────▼────┐
   │ 容器运行时 │                                  │ 容器运行时 │
   └─────────┘                                  └─────────┘
```

## 2. 硬性约束（不可违背的设计红线）

1. **主程序绝不直连容器运行时**。所有对 Docker/Podman/containerd 的操作，必须经由已建立连接的 Agent 中转。主程序侧不持有任何机器的 docker.sock 或 remote API 端点。
2. **Agent 必须能离线自治**。主程序不可用时，Agent 仍能：查看本机容器、启停容器、依据本地编排文件重建/维护容器、操作本地镜像。
3. **编排文件双份保存**。主程序和 Agent 本地各有一份，且都带版本号与内容哈希。
4. **凭据不下发到 Agent 的持久化存储**。镜像仓库凭据集中在主程序，Agent 拉镜像时向主程序换取短期凭据，用完即弃。

## 3. 连接协议

### 3.1 建连方式

Agent 主动向 Hub 发起 WebSocket 连接（`wss://hub/agent/connect`），携带：

- Agent ID（注册时由 Hub 分配）
- Agent 版本号、支持的协议版本、运行时能力清单
- 双向 TLS 客户端证书（或预共享的 Agent Token 换取会话）

Hub 通过 Origin/证书/Token 三重校验后，将该连接加入在线 Agent 表。

### 3.2 消息信封

统一信封结构，请求与响应通过 `request_id` 关联：

```json
{
  "v": 1,
  "id": "uuid",
  "type": "request | response | event | ack",
  "method": "container.list",
  "target": "agent:xxx",
  "ts": 1700000000,
  "payload": { },
  "error": { "code": "", "message": "" }
}
```

`type=event` 用于 Agent 主动上报（容器状态变化、任务进度、心跳），不经请求响应配对。

### 3.3 心跳与断线

- 心跳间隔 15s，连续 3 次未响应判定离线。
- 断线后 Agent 按指数退避重连（1s → 2s → 4s … 上限 60s）。
- 重连后 Agent 上报**全量状态快照 + 版本号**，Hub 以此对账，避免增量丢失导致的“幽灵状态”。
- 断线期间 Hub 产生的下发任务进入 Agent 的待办队列（持久化），重连后按序执行。

## 4. 状态模型

### 4.1 Agent 状态（Hub 侧）

| 字段 | 含义 |
| --- | --- |
| `agent_id` | 稳定标识，绑定服务器 |
| `status` | online / offline / upgrading |
| `version` | Agent 版本 |
| `runtime` | 探测到的运行时类型与版本 |
| `last_seen` | 最后心跳时间 |
| `labels` | 用户自定义标签（环境、机房、分组） |

### 4.2 容器归属（关键）

每个被纳管的容器必须记录**来源（origin）**：

| origin | 含义 | 行为 |
| --- | --- | --- |
| `arkade` | 由 Arkade 下发的编排创建 | 可自动重建、可改编排 |
| `adopted` | 外部工具（如宝塔）部署后被接管 | 编排只读快照，不擅自重建 |
| `discovered` | 手工或默认存在，被发现但未接管 | 操作受限：仅展示与基础操作 |

没有来源标记，就无法判断“这个容器被删掉后该不该自动拉起”，这是接管功能的基础。

### 4.3 编排文件双份模型

两份文件各自维护版本：

```
Hub 侧：{ stack_id, version, hash, content, updated_at, updated_by }
Agent 侧：{ stack_id, version, hash, content, updated_at, source_of_truth }
```

两种写入路径：

- **Hub 下发**：Hub 版本 +1 → 推给 Agent → Agent 落盘 → 回报新 hash → Hub 确认。
- **Agent 本地变更**（离线时）：Agent 版本 +1 → 重连后上报 → Hub 比对 hash。

冲突处理：任一侧 hash 与 Hub 记录的基线不一致即判定冲突，**不自动合并、不静默覆盖**，由人工选择保留哪份。这是防止“两边各改各的、互相覆盖丢配置”的唯一可靠方式。

## 5. 安全边界

- Hub ↔ Agent 走 TLS，Agent 用客户端证书或 Token 认证。
- 危险操作（删除、清卷、覆盖编排、迁移）需要显式确认，并记录到审计日志。
- 用户权限分级：查看 / 操作 / 管理三档，管理档才能改 Agent 与凭据。
- 审计日志记录：操作人、时间、目标 Agent、方法、参数摘要、结果。

## 6. 与 Portainer 的差异定位

| 维度 | Portainer | Arkade |
| --- | --- | --- |
| 控制方式 | 主服务直连各节点 Docker API | 主程序不直连，只经 Agent |
| 网络要求 | 通常需节点入站可达 | Agent 反向连接，NAT/内网后可管 |
| 断连表现 | 主服务不可用则无法管理 | Agent 离线自治 |
| 编排存储 | 集中在 Portainer | 双份，服务器本地也可执行 |
| 既有容器 | 接管支持弱 | 显式来源标记与只读接管 |
| 仓库凭据 | 逐环境配置 | 集中配置、临时换取 |
| 迁移 | 无原生迁移 | 配置+镜像+卷一体迁移，支持无外网环境 |
